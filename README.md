# ShiftSchedule Frontend

Приложение на Vue 3, TypeScript и TanStack Vue Query. Vite запускает приложение, Storybook — каталог компонентов. Компоненты используют модульные SCSS-стили; шрифт Manrope поставляется локально вместе с приложением.

Макет интерфейса: [тестовое задание в Figma](https://www.figma.com/design/mHzFfUsquaFCsUGUfNrtnh/%D0%A2%D0%B5%D1%81%D1%82%D0%BE%D0%B2%D0%BE%D0%B5-%D0%B7%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5-%D1%80%D0%B0%D0%B7%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D1%87%D0%B8%D0%BA--Copy-?node-id=0-1&p=f&t=TeFx2GtDm7jL89Ox-0).

## Перед запуском

Выберите один из двух вариантов ниже: Docker Compose или локальный Node.js с npm. Оба используют порты `5173` и `6006`, поэтому перед переключением между ними остановите предыдущий вариант или измените порты.

При первом запуске создайте локальный файл настроек из шаблона командой **`cp .env.example .env`**. Если `.env` уже существует, сохраните его настройки и пропустите копирование. Шаблон `.env.example` не нужно перезаписывать содержимым локального `.env`.

Все команды ниже выполняются из корня этого репозитория, где находятся `package.json`, `compose.yaml` и `Makefile`. Storybook можно использовать самостоятельно.

## Вариант 1: запуск через Docker

Нужны Docker с поддержкой Compose v2 и запущенный Docker Engine (например, Docker Desktop). Node.js и npm на компьютере устанавливать не требуется.

В корне репозитория выполните:

```sh
cp .env.example .env
docker compose up -d --build --wait --remove-orphans
```

При установленном Make последнюю команду можно заменить на `make up`.

- Приложение: [http://localhost:5173](http://localhost:5173).
- Storybook: [http://localhost:6006](http://localhost:6006).

Compose запускает Vite и Storybook одновременно. При каждом старте контейнеров выполняется `npm ci` из `package-lock.json`; зависимости хранятся в отдельном Docker-томе каждого сервиса. Первый запуск может занять несколько минут.

Vite перенаправляет `/api` на `http://host.docker.internal:8000`. Для стандартного запуска оставьте `API_PROXY_TARGET` закомментированным в `.env`.

Управление контейнерами:

```sh
docker compose ps
docker compose logs -f app
docker compose logs -f storybook
docker compose down --remove-orphans
```

Остановка сохраняет тома зависимостей. Эквиваленты через Make: `make ps`, `make logs SERVICE=app`, `make logs SERVICE=storybook`, `make down`.

## Вариант 2: запуск через npm

Нужны Node.js **26+** и npm. Версия Node.js указана в `.nvmrc`; этот же runtime используется в Docker. Если используете nvm, выполните `nvm install` и `nvm use` в корне репозитория перед установкой зависимостей.

В корне репозитория выполните:

```sh
cp .env.example .env
npm ci
npm run dev
```

Приложение откроется по адресу [http://localhost:5173](http://localhost:5173). Vite перенаправляет `/api` на `http://127.0.0.1:8000`. Для стандартного запуска оставьте `API_PROXY_TARGET` закомментированным в `.env`.

Для Storybook откройте **второй терминал** в корне репозитория и выполните:

```sh
npm run storybook
```

Каталог компонентов доступен по адресу [http://localhost:6006](http://localhost:6006). Для остановки каждого dev-сервера нажмите `Ctrl+C` в его терминале. После изменения зависимостей выполните `npm ci` и запустите серверы снова.

Проверки и сборки:

```sh
npm run typecheck
npm test
npm run check             # Линтер, форматирование, типы и тесты
npm run build             # Production-сборка приложения в dist/
npm run build-storybook   # Статический Storybook в storybook-static/
npm run preview           # Локальный просмотр готовой сборки после npm run build
```

Приложение и Storybook публикуются одним сайтом:

Он устанавливает зависимости через `npm ci`, запускает линтер, проверку форматирования, типов и тесты, затем собирает приложение в `dist/`, а Storybook — в `dist/storybook/`. Обе сборки публикуются вместе после успешных проверок.

Для первоначальной настройки репозитория выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**. Путь приложения определяется через `actions/configure-pages`; Storybook использует относительные пути к ресурсам. Локальные команды запуска остаются прежними. Подробнее: [GitHub Pages с собственным workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

В **Settings → Secrets and variables → Actions → Variables** можно добавить переменные репозитория:

| Переменная          | Значение по умолчанию                                | Назначение                        |
| ------------------- | ---------------------------------------------------- | --------------------------------- |
| `VITE_API_BASE_URL` | `https://test.api.shift-schedule.videoscale.pro/api` | Полный HTTPS-адрес API без версии |
| `VITE_SCHEDULE_ID`  | `00000000-0000-4000-8000-000000000001`               | Идентификатор графика             |

По умолчанию приложение обращается к API на `https://test.api.shift-schedule.videoscale.pro/api`. Версия API добавляется в пути конкретных запросов. Storybook работает независимо. После изменения переменных запустите workflow заново: настройки встраиваются во время сборки, локальный `.env` в GitHub Actions не используется.

GitHub Pages раздаёт статические файлы и не предоставляет прокси `/api`. API должен быть доступен по HTTPS и разрешать CORS для origin `https://toxanetoxa.github.io` — без пути `/ShiftSchedule.frontend/`. Значения `VITE_*` доступны посетителю в JavaScript, поэтому секреты в них не размещают.

npm run build-storybook -- --output-dir dist/storybook

Откройте `http://localhost:4173/ShiftSchedule.frontend/` и `http://localhost:4173/ShiftSchedule.frontend/storybook/`. Сгенерированный `dist/` исключён из Git.

## Рабочее приложение

На `localhost:5173` открывается рабочий редактор с загрузкой, сохранением ячеек и публикацией через API; Storybook остаётся независимым каталогом компонентов без HTTP-записи.

Клик добавляет ячейку к выделению, повторный клик снимает только её выделение. Назначьте шаблон выбранным ячейкам справа, введите своё время либо перетащите шаблон в календарь. Shift выделяет прямоугольную область. Изменения видны сразу, а запрос записи выполняется только по «Сохранить». Перенос назначенной смены отправляется одним пакетом с очисткой источника и назначением цели; занятая цель требует подтверждения. Поиск скрывает строки и не очищает черновик или назначения остальных сотрудников.

Навигация по неделям и месяцам, переход к дате и переход на главную с несохранёнными правками предлагают сохранить, отбросить изменения или остаться. Во время сохранения редактирование и повторные операции заблокированы. При закрытии вкладки с черновиком браузер показывает стандартное предупреждение; асинхронное сохранение при закрытии не обещается.

Календарь сверяется с сервером каждые 5 секунд, при возвращении к вкладке и восстановлении связи. Локальные правки сохраняются поверх новых данных. Чужая версия требует явного согласования; диалог показывает конфликтующие ячейки. Поздние ответы не понижают принятую версию. После сетевой ошибки записи повторный запрос не отправляется автоматически: сначала выполняется чтение и согласование результата.

«Опубликовать» показывает явный диапазон от 1 до 62 дней с исключённой конечной датой. При наличии черновика сначала выполняется Save, затем публикация именно его подтверждённой версии. Опубликованный снимок открывается отдельно, доступен только для чтения и имеет ссылку вида `#publication=<uuid>`; после перезагрузки эта ссылка запрашивает тот же снимок. Главная показывает единственный доступный график. Диалог уведомлений пока пуст.

## SCSS и модульные стили

Sass подключён к Vite, Storybook и Vitest. Все компоненты интерфейса с собственными стилями используют `<style module lang="scss">`: классы доступны в шаблоне через `$style`, а состояния и дочерние элементы оформляются через вложенность SCSS.

```vue
<template>
  <button :class="$style.action">Действие</button>
</template>

<style module lang="scss">
.action {
  color: var(--schedule-color-label-primary);

  &:hover {
    background: var(--schedule-color-surface-primary);
  }
}
</style>
```

Стили остаются внутри SFC; `scoped` для этого блока не требуется. Цвета и размеры берите из существующих CSS-токенов. Prettier форматирует SCSS в составе Vue-файла. После обновления зависимостей выполните `make restart`, чтобы оба Docker-сервиса установили Sass из lock-файла.

Повторяющиеся правила находятся в `src/shared/styles/`: `dialog` содержит оболочку и элементы диалогов, `shift-template` — оформление карточки шаблона, `workspace` — раскладку редактора. Миксины подключаются через `@use` внутри SFC. Классы для раскладки дочерних компонентов передаются через `:class`; обращаться к их внутренним классам через `:deep` не требуется. `UiDialog` поддерживает `variant="default"`, `variant="drawer"` и `variant="wide"`, а `CoverageRow` — закрепление через `sticky`.

## Настройки API и портов

Настройки обоих вариантов запуска находятся в `.env`, созданном из `.env.example`. Локальный `.env` исключён через `.gitignore`; `.env.example` служит шаблоном. По умолчанию используются `FRONT_PORT=5173`, `STORYBOOK_PORT=6006`, `VITE_API_BASE_URL=/api`, `VITE_SCHEDULE_ID=00000000-0000-4000-8000-000000000001`.

`VITE_API_BASE_URL` содержит адрес API без версии. Версия указывается в функциях запросов: например, `requestJson('v1/schedules/...')` обращается к `/api/v1/schedules/...`. Общий клиент `src/shared/api/client.ts` соединяет базовый адрес с переданным путём и не выбирает версию API.

`STORYBOOK_PORT` меняет порт в Compose. Для локального Storybook используйте аргумент CLI, например `npm run storybook -- --port 6007`. Ссылку на каталог в приложении можно переопределить через `VITE_STORYBOOK_URL`.

`API_PROXY_TARGET` задаёт адрес назначения Vite-прокси для запросов `/api`: без Docker это `http://127.0.0.1:8000`, внутри Compose — `http://host.docker.internal:8000`. При необходимости задайте адрес, доступный из выбранного окружения. После изменения `.env` выполните `make restart` либо перезапустите локальный Vite.

Для production задайте полный `VITE_API_BASE_URL` перед сборкой, например `https://api.example.com/api`, или используйте `/api`, если на домене приложения настроен прокси `/api`. Переменные `VITE_*` входят в клиентскую сборку; секреты в них хранить нельзя.

## Импорты и алиасы

Общие компоненты экспортируются из `src/shared/ui/index.ts`, компоненты графика — из `src/features/schedule/ui/index.ts`. Используйте именованные импорты:

```ts
import type { CellRef } from '@schedule/domain/types'
import { ScheduleGrid, SelectionToolbar } from '@schedule/ui'
import { UiButton, UiDialog } from '@ui'
```

| Алиас       | Каталог                 |
| ----------- | ----------------------- |
| `@ui`       | `src/shared/ui`         |
| `@schedule` | `src/features/schedule` |
| `@`         | `src`                   |

Для экспорта компонентов нужен `index.ts`: он участвует в сборке приложения. Файлы `index.d.ts` содержат только объявления типов и не создают исполняемые экспорты. Новый компонент добавляйте в соответствующий `index.ts`; stories и тесты туда не экспортируются.

Внутри одной библиотеки UI импортируйте соседние компоненты напрямую, например `import UiIcon from '@ui/UiIcon/UiIcon.vue'`, чтобы не создавать циклы через собственный `index.ts`. Компонент графика может импортировать общие компоненты из `@ui`, а своих соседей — по пути `@schedule/ui/Имя/Имя.vue`. В stories и тестах импорт проверяемого компонента можно оставить относительным: `./Имя.vue`.

`App.vue` импортирует рабочую страницу напрямую через алиас, чтобы не подключать offline-композицию `ScheduleWorkspace` и её демоданные через общий модуль.

Алиасы определены в `config/aliases.ts` и подключены к Vite, Vitest и Storybook. Соответствующие `paths` в `tsconfig.json` обеспечивают проверку типов и навигацию в редакторе. В SCSS также доступен алиас `@`, например `@use '@/shared/styles/dialog';`.

## Структура проекта

- `src/app/` — QueryClient и общий вход стилей.
- `src/shared/api/` — HTTP-клиент с обработкой ошибок и отменой запросов.
- `src/shared/ui/` — общие компоненты и их stories.
- `src/features/service/api/` — типизированный запрос состояния существующего API.
- `src/features/schedule/api/` — DTO, проверка ответов, HTTP-функции и реактивные ключи Vue Query.
- `src/features/schedule/model/` — отдельный черновик, согласование серверных версий, Save/Publish и защита переходов.
- `src/features/schedule/ui/SchedulePage/SchedulePage.vue` — рабочий экран из готовых компонентов; `PublicationView/PublicationView.vue` показывает неизменяемый снимок.
- `.storybook/` — настройки каталога компонентов, общий CSS и доступность.

В `src/shared/ui/` и `src/features/schedule/ui/` каждый компонент хранится в отдельной папке с одноимённым `.vue`-файлом, его `.stories.ts` и тестами `.test.ts`, если они есть. Например: `src/shared/ui/UiButton/UiButton.vue` и `UiButton.stories.ts` рядом.

## Библиотека интерфейса

Компоненты оформлены по исходным токенам; интерактивные примитивы используют Reka UI. В Storybook доступны:

- `UI` — кнопки, иконки, аватар, бейджи, popover, dialog, tooltip и toast.
- `Layout` — оболочка приложения и управляемое боковое меню.
- `Schedule` — поиск, переключатель недели/месяца, навигация дат, поля времени, форма собственной смены, карточки шаблонов и назначений, ячейки, сотрудники, покрытие и статусы.
- Панели инструментов, меню ячейки/даты/выбора шаблона, диалоги публикации, замены, несохранённых изменений и согласования конфликтов.
- `Schedule/Workspace` — составные offline-примеры: пустая и заполненная неделя, месяц, восемь выделенных ячеек, смена 10:00–23:00, ошибки, внешнее обновление и конфликт. Viewport 1700/1366/768 переключается в Storybook; ниже 1100 px редактор открывается в drawer.

Компоненты принимают данные через props и передают типизированные действия через emits. `ScheduleGrid` использует одну геометрию колонок для заголовков, строк и покрытия. Поддерживаются roving focus, стрелки, Home/End, Ctrl+Home/End, Shift+стрелки, Space, Enter, контекстное меню и очистка. `Ctrl+Enter` открывает действие даты. Выделение не означает изменение данных. Для покрытия полного состава при поиске передавайте `coverageCounts`, вычисленные до фильтрации строк.

`TimeField` и `CustomShiftForm` проверяют HH:mm, блокируют равные времена и применение без выделения. Ночная смена явно показывает переход на следующий день и передаёт `endDayOffset: 1` только по кнопке применения. Диалоги удерживают и возвращают фокус, блокируют закрытие при pending, показывают ошибки; решение конфликтов сбрасывается при новой серверной версии.

Состояния компонентов описаны в stories. Иконки используют `currentColor` и наследуют цвет текста.

В `src/features/schedule/ui/ScheduleWorkspace/ScheduleWorkspace.vue` назначения, поиск, выделение и drag-and-drop работают на локальных демонстрационных данных. Сохранение и публикация показывают передаваемые команды; HTTP-запись не имитируется. Production-приложение использует отдельный `SchedulePage` и настоящие API-данные, без импорта stories и fixtures.

## Перетаскивание смен

Откройте [интерактивный пример](http://localhost:6006/?path=/story/schedule-workspace--drag-and-drop) в Storybook. Можно перенести шаблон из панели на ячейку без предварительного выделения. Шаблон остаётся в панели; в календаре появляется отдельное назначение. Перенос назначенной смены очищает источник и заполняет цель одним локальным действием. Занятая цель требует явного подтверждения замены; отмена оставляет обе ячейки без изменений.

`ScheduleDragDrop` объединяет источники и цели через официальный `@dnd-kit/vue`. `ScheduleGrid` и `ShiftTemplatePanel` включают DnD через `dragEnabled`; вне provider продолжают работать как обычные UI-компоненты. Preview не изменяет данные, допустимые и запрещённые цели подсвечиваются. Отпускание вне фактической ячейки и Escape отменяют перенос. Мышь начинает перенос после движения на 8 px; на сенсорном экране сначала удерживайте источник 250 ms. Чтобы браузер не прервал перенос прокруткой, на источниках отключён нативный pan: прокручивайте сетку за заголовки или пустые ячейки, а панель — за отступы. На узком экране доступны шаблоны над сеткой, не перекрытые модальным drawer.

Альтернатива без перетаскивания: откройте меню ячейки через правую кнопку мыши или Shift+F10 и выберите «Перенести смену…». Также можно начать перенос сочетанием Alt+стрелка. Затем выберите цель обычным нажатием либо стрелками и Enter; Escape или кнопка отмены завершает режим без изменений. Для назначения шаблона с клавиатуры можно выделить ячейки и применить шаблон кнопкой.

`domain/operations.ts` используется и переносом, и явными командами назначения/очистки. Проверяются активность целевого сотрудника, корректность времени и пересечения с загруженными соседними сменами. Перенос проверяет итоговый набор сразу после очистки источника и назначения цели; соприкасающиеся интервалы разрешены. Dirty-набор пересчитывается относительно baseline, поэтому возврат смены на исходное место убирает отменённые правки. `model/useScheduleTransfers.ts` хранит неизменяемые снимки источника/цели и повторно проверяет их при подтверждении замены.

Эти проверки локальные и используют загруженные назначения. Подключённый календарный API отвечает за полные ограничения, часовой пояс и соседние даты за пределами загруженных данных.

Тесты в `src/**/*.test.ts` проверяют форму и ночные смены, клавиатурное выделение, сброс выделения при поиске, сохранение покрытия, фокус диалогов, pending и обновление решений конфликтов.

В `package.json` узкие overrides для зависимостей форматтера `js-beautify` устраняют уязвимые транзитивные `glob`/`minimatch`, используемые инструментами тестирования.

TypeScript закреплён на совместимой ветке 6: текущий официальный `vue-tsc` не поддерживает TypeScript 7 ([известная проблема Vue Language Tools](https://github.com/vuejs/language-tools/issues/6124)).
